# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

OmniRose is a free, static web app for sailors: deviation readings in, printable PDFs out (the OmniRose conversion rose, deviation tables, swing records), plus an experimental "swing by the sun" tool. It is plain HTML, CSS and ES modules with **no build step and no dependencies**, served by GitHub Pages from the root of `master`. Pushing `master` deploys the live site at https://omnirose.github.io/.

## Commands

```sh
python3 -m http.server 8000          # serve locally (file:// won't load ES modules); .claude/launch.json uses port 8765
node --test                          # all tests (Node 20+, built-in runner, no npm install)
node --test tests/curve.test.js      # one file
node --test --test-name-pattern="state round trip"   # one test by name
node tools/build-images.js           # regenerate img/example-*.svg after changing drawing code
node tools/build-icon.js             # regenerate img/icon.svg (the logo)
```

`img/icon-512.png` and `img/og.png` aren't generated by a script. The PNG icon was rendered from `img/icon.svg` with headless Chrome. CI (`.github/workflows/test.yml`) runs `node --test` on pushes to `master` and on pull requests. The README has a manual release checklist covering printing and QR scanning.

## Architecture

**Pages and entry modules.** Each interactive page loads one module: `make/` → `js/make.js` (the main tool), `sun/` → `js/sun-page.js`, `learn/swinging.html` → `js/record-page.js` (blank swing sheets), `about.html` → `js/contact.js`. Everything else is shared library code with no DOM access, which is what the tests import.

**Drawing once, rendering twice.** `js/draw/*.js` (rose, table, record, pelorus) draw onto a small surface interface (`line`, `polyline`, `circle`, `rect`, `text`, `link`, …) from `js/draw/surface.js`, which has an `SvgSurface` for the on-screen preview and a hand-written `PdfSurface` for downloads, so the two always match. The PDF uses built-in Helvetica with WinAnsi encoding: no embedded fonts, and characters outside Windows-1252 (such as `−` or `✓`) print as `?`. Text layout uses the Helvetica metrics in `js/draw/font.js`. QR codes come from the project's own encoder (`js/qr.js`). The page is 590 × 790 pt, which fits both A4 and US Letter.

**Maths.** `js/curve.js` fits deviation as a Fourier series in heading by least squares, chooses the number of terms by BIC (an override is allowed), and converts between compass, magnetic and true. `js/wmm.js` evaluates NOAA's World Magnetic Model from `data/WMM.COF`, which must be replaced every 5 years (see `data/README.md`). `js/sun.js` gives the sun's position (NOAA algorithm), and `js/sunswing.js` turns shadow readings into deviations.

**State lives in the URL hash.** A bookmark or shared link *is* the saved work, and each printout's QR code links back to it. The formats are documented in `js/state.js` (make page) and `js/sunswing.js` (sun page). **Old links must keep working**: only add keys, and convert retired ones on decode (for example, `cd=` can diameter becomes `e=` edge reading). `js/remember.js` also keeps a copy of the latest hash in `localStorage`, so following a nav link away and back restores it ("Start afresh" clears it).

## Conventions that aren't obvious from one file

- **Signs:** readings are against **magnetic** heading. East is positive for deviation and variation. Deviation = magnetic − compass, so the compass reading less than magnetic means East. Typing a minus in a deviation field selects W.
- **Notation:** printouts use a superscript M, T or C in place of the degree sign (`45ᴹ`), because space is tight. Prose uses `045°M`. Deviation and variation are amounts, not bearings, and are written `3°E` and `2°W`.
- **Naming:** the card is an **OmniRose**: say so in buttons, headings, PDF titles and file names. Page titles, meta descriptions and the first mention on a page still say "conversion rose", so people searching for one find the site.
- **Sun pelorus:** only the **anticlockwise** shadow edge is read, because a moving boat lets you read only one thing at a time. The user enters where that edge falls with the sun dead ahead (where their can's snail line meets the scale, 336 for a standard can), and offset = 360 − that reading. There's a single outer scale. Don't auto-correct card misalignment by assuming deviation coefficient A = 0, because that would also hide a real lubber-line error. The sun feature is labelled **Experimental**, with links asking for feedback.
- **Privacy claims on the About page are promises:** no cookies, analytics or servers, and nothing leaves the browser. "Email these readings" is a `mailto:` link to no one. The contact address is put together in JavaScript on click and must never appear as plain text in the source.
- **Tone and spelling:** cheerful and educational for cruising sailors who may be new to deviation, in British spelling (colour, licence). Don't overclaim. For example, checking a compass against the sun is an old navigator's technique, not something OmniRose invented.

## Gotchas

- When a shared module gains a new export, a browser holding a cached older copy will fail on import and the page script stops (for example, the examples list goes missing). Locally, refresh with `fetch(url, {cache: "reload"})` for each changed file, then reload. In production it clears within GitHub Pages' 10-minute cache.
- Changing drawing code changes `img/example-*.svg` only after `node tools/build-images.js` is run. Commit the regenerated images with the change.
